# Delamain Training Analysis Tools

This directory contains scripts for analyzing training results from the Delamain RL project.

## Analysis Script

The `analyze_results.py` script provides comprehensive analysis capabilities for your training runs.

### Features

- **Single Run Analysis**: Detailed analysis of individual training runs
- **Multi-Run Comparison**: Compare performance across different experiments
- **Visualizations**: Generate plots for learning curves, action distributions, and training metrics
- **Configuration Tracking**: Parse YAML config files to understand experimental setup
- **Statistical Summaries**: Get key metrics and performance indicators

### Installation

The script requires standard Python data science libraries:
```bash
pip install matplotlib numpy pyyaml
```

### Usage

#### 1. Single Run Analysis

Analyze a single training run with visualizations:

```bash
python analyze_results.py single --log training/logs/YourModel_log_test.csv --config training/logs/YourModel_config.yaml
```

This will generate:
- Learning curve plot
- Action distribution analysis
- Training metrics grid
- All plots saved to `analysis/` directory

#### 2. Compare Multiple Runs

Compare performance across different experiments:

```bash
python analyze_results.py compare --logs run1.csv run2.csv run3.csv --configs run1.yaml run2.yaml run3.yaml
```

This generates:
- Comparison table with key metrics
- Combined learning curve plot
- Parameter efficiency analysis (if available)
- All plots saved to `analysis/` directory

#### 3. Show Run Information

Get detailed information about a training run:

```bash
python analyze_results.py info --log training/logs/YourModel_log_test.csv --config training/logs/YourModel_config.yaml
```

### Output Files

The script generates several types of plots in the `analysis/` directory:

- **learning_curve.png**: Reward progression over episodes (with moving average)
- **{run_name}_action_distribution.png**: Action frequency and patterns
- **{run_name}_training_metrics.png**: Grid of all training metrics
- **parameter_efficiency.png**: Max reward vs model size (comparison only)

### Example Workflow

1. **After training completes**:
   ```bash
   # Analyze the completed run
   python analyze_results.py single --log training/logs/Delamain_2_6_log_test.csv --config training/logs/Delamain_2_6_config.yaml
   ```

2. **Compare multiple experiments**:
   ```bash
   # Compare different models or hyperparameters
   python analyze_results.py compare --logs baseline.csv improved.csv --configs baseline.yaml improved.yaml
   ```

3. **Quick information check**:
   ```bash
   # Get summary of a run
   python analyze_results.py info --log training/logs/latest_run.csv
   ```

### Configuration Files

The script works with the YAML configuration files generated by the enhanced logging system:

- **training_params**: All training hyperparameters
- **model_info**: Architecture details and parameter counts
- **environment**: Wrapper chain and observation space
- **system_info**: Software versions and hardware
- **git_commit**: Version control tracking

### Advanced Usage

#### Custom Output Directory

```bash
python analyze_results.py single --log your_run.csv --output custom_analysis
```

#### Analysis Without Config

If you don't have a config file, you can still analyze the CSV logs:

```bash
python analyze_results.py single --log your_run.csv
```

### Interpretation Guide

#### Learning Curve
- **X-axis**: Training episodes
- **Y-axis**: Episode reward
- **Smooth line**: Moving average (window = 20 or 10% of total episodes)
- **Points**: Key milestones (start, 25%, 50%, 75%, end)

#### Action Distribution
- Shows average number of consecutive identical actions
- Higher values may indicate lack of exploration or policy convergence
- Moving average helps identify trends

#### Training Metrics Grid
- Multiple subplots showing different training aspects
- Includes reward, loss, epsilon, learning rate, episode length

### Tips

1. **Regular Analysis**: Run analysis after every major training milestone
2. **Version Control**: Commit analysis results alongside your training logs
3. **Comparison Naming**: Use descriptive names for runs (e.g., `DQN_lr0.001.csv`)
4. **Visual Inspection**: Always check the generated plots for anomalies

### Troubleshooting

- **Missing metrics**: Ensure your CSV logs contain the expected columns
- **YAML errors**: Verify your config files are valid YAML
- **Plot issues**: Check matplotlib installation and backend configuration

## Implementation Details

The analysis script uses:
- **Matplotlib** for visualization
- **NumPy** for numerical operations
- **PyYAML** for configuration parsing
- **CSV** module for log file reading

All visualizations use the `seaborn` style for professional appearance.
